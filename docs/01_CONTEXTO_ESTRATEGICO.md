# Contexto estratégico completo

## Identidad del proyecto

- Nombre definitivo: **HOSRIA**.
- Organización y contexto: Deloitte, área de Auditoría y Assurance.
- Formato elegido: página web narrativa e interactiva.
- Lenguaje visual: navegación espacial con zoom, inspirada en Prezi y en mapas de relaciones como Obsidian.

Durante etapas iniciales apareció el nombre OSIRA/HOSIRA. Toda comunicación nueva debe utilizar exclusivamente **HOSRIA**.

## Punto de partida de la presentación

La presentación web corresponde a la segunda parte de una experiencia mayor. Comienza inmediatamente después de un video introductorio de aproximadamente 60 a 80 segundos que muestra:

- exceso de mensajes y notificaciones;
- múltiples correos y archivos;
- información desordenada y repetida;
- sobrecarga administrativa;
- distintas versiones de un mismo dato;
- un “switch” o apagón que marca el cambio de paradigma.

Después de ese switch aparece HOSRIA como la plataforma que hace posible un nuevo orden.

## Idea fuerza

HOSRIA no debe presentarse como “otro sistema” ni como una colección de pantallas. Debe entenderse como el **sistema nervioso de Deloitte**: el lugar donde la información deja de estar dispersa y se convierte en un activo único, conectado, reutilizable y gobernado.

La propuesta puede resumirse así:

> Una única verdad para todos los procesos.

Y su regla de experiencia más clara es:

> Si ya lo sabemos, no lo volvemos a pedir.

## Concepto central: gobernanza de datos

HOSRIA busca que la información sea:

- **Única:** no existen versiones paralelas del mismo dato.
- **Conectada:** los datos comunes alimentan múltiples procesos.
- **Reutilizable:** un dato cargado una vez puede servir en nuevos módulos y reportes.
- **Gobernada:** se conoce su origen, responsable, aprobación y uso.
- **Disponible:** cada proceso accede a lo que necesita cuando lo necesita.
- **Confiable:** dashboards, indicadores y decisiones parten de una misma realidad.

## Problema actual

La información y los procesos se encuentran distribuidos en distintos medios y criterios de trabajo.

Ejemplos mencionados:

- propuestas enviadas por distintos canales;
- aprobaciones que pueden omitirse o que nadie controla;
- reportes solicitados por correo;
- múltiples Excel;
- información repetida;
- distintas versiones de un mismo dato;
- comunicaciones manuales;
- datos que se vuelven a pedir una y otra vez;
- compilación y seguimiento manual.

Consecuencias:

- pérdida de tiempo;
- trabajo administrativo repetitivo;
- datos inconsistentes;
- múltiples fuentes para un mismo dato;
- imposibilidad de reutilizar información;
- poca trazabilidad;
- decisiones basadas en realidades diferentes.

## Qué hace HOSRIA

La plataforma busca:

- centralizar la información;
- evitar la duplicación de datos;
- conectar procesos;
- generar una única fuente de verdad;
- reducir tareas administrativas;
- automatizar flujos;
- reutilizar información existente;
- construir una base de conocimiento corporativa;
- mejorar la toma de decisiones con datos confiables.

## Cómo nació

HOSRIA nació resolviendo problemas concretos y fue creciendo hacia una plataforma compartida.

### Primer módulo: gestión de propuestas

Antes:

- no existía un lugar único con todas las propuestas comerciales;
- cada socio gestionaba el proceso de manera distinta;
- las aprobaciones podían omitirse;
- no había una trazabilidad uniforme.

Con HOSRIA:

- todas las propuestas se crean en un único lugar;
- el sistema identifica automáticamente quién debe aprobar;
- las aprobaciones siguen un flujo automático;
- el estado del proceso puede ser controlado.

Este módulo representa el primer paso hacia la centralización.

### Segundo módulo: reportes requeridos

Antes:

- solicitudes por correo;
- formatos diferentes;
- seguimiento manual;
- recordatorios personales;
- compilación manual.

Con HOSRIA:

- los reportes se solicitan desde la plataforma;
- existen recordatorios automáticos;
- la información se carga con un formato uniforme;
- las aprobaciones están centralizadas;
- un dashboard permite realizar seguimiento.

### Próximos módulos conceptuales

Estos módulos sirven para demostrar que el mismo núcleo puede soportar capacidades especializadas. La presentación no necesita explicar cada función en profundidad.

#### Gestión SEGUN

- asignación de cartera;
- administración de clientes;
- asignación de profesionales;
- filtros;
- diferentes vistas operativas.

#### Gestión MVPD

- funciones específicas para otro rol operativo;
- acceso al mismo ecosistema de información;
- reutilización de atributos comunes.

#### Comunicaciones

Módulo para distribuir información segmentada, por ejemplo:

- días de licencia;
- cursos pendientes;
- notificaciones personalizadas;
- datos dirigidos únicamente a quien corresponde.

Hoy estas comunicaciones implican Excel, correos individuales y mucho trabajo manual. La idea futura es cargar la información una vez y que HOSRIA distribuya automáticamente el contenido correcto a cada persona.

## Valor de plataforma

### Menos burocracia

Las personas dejan de responder varias veces la misma información y disminuyen las tareas de control manual.

### Una única fuente de verdad

El mismo dato conserva su significado sin importar qué módulo, reporte o dashboard lo consulte.

### Información conectada

Un cliente puede tener atributos comunes como industria, socio responsable, gerente, categoría y otros. Cualquier proceso posterior puede reutilizarlos.

### Información reutilizable

La carga deja de pertenecer a un formulario aislado y pasa a formar parte del patrimonio informacional de la organización.

### Base de conocimiento corporativa

Cada módulo contribuye a una memoria común y progresivamente más valiosa.

### Mejor toma de decisiones

Los indicadores, consultas y análisis se construyen sobre datos consistentes y comparables.

## Qué debe transmitir la presentación

- HOSRIA está en el centro.
- Los módulos no son islas.
- La información fluye entre procesos.
- Cada nuevo módulo amplía el valor del núcleo.
- Gobernar los datos reduce burocracia.
- La información confiable permite decidir mejor.

## Qué no debe hacer

- no recorrer funcionalmente todas las pantallas;
- no convertirse en una capacitación del sistema;
- no explicar cada módulo con el mismo nivel de detalle;
- no parecer una presentación de PowerPoint tradicional;
- no reducir HOSRIA a un listado de funcionalidades;
- no prometer como implementado aquello que aún es conceptual.

## Estructura general de producción

### Bloque 1: video inicial

- Duración estimada: 60–80 segundos, sujeto a guion.
- Historia: caos, sobrecarga y desorden.
- Punto de quiebre: apagón/switch.
- Resultado: aparición del nuevo orden.
- Es la parte con mayor necesidad de iteración creativa.

### Bloque 2: presentación web de HOSRIA

- Aparición del núcleo.
- Explicación de gobernanza de datos.
- Mapa del ecosistema.
- Zoom a algunos módulos.
- Conexiones y reutilización.
- Cierre sobre conocimiento y toma de decisiones.

### Bloque 3: demostración futura

- Video breve de aproximadamente 15–20 segundos.
- Mostrará la plataforma real en funcionamiento.
- Depende de una nueva versión de la aplicación y de un guion específico.

## Materiales prometidos por el equipo

- enlaces de los módulos;
- pantallas seleccionadas;
- presentación de referencia estética;
- indicación exacta de qué vistas usar;
- guion del video demostrativo futuro.

La selección de pantallas no forma parte de esta primera versión conceptual.
